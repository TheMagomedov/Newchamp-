# ТОиР-Проф: нативный клиент Windows

Рабочий клиент WPF / C# для общего FastAPI-сервера. Все данные читаются и изменяются через HTTP API. Клиент не содержит подключения к SQL Server, WebView, Electron, Tauri или встроенного браузера. Основное приложение не требует внешних NuGet-пакетов; отдельный проект MSTest использует пакеты с закреплёнными версиями и `tests/packages.lock.json`.

## Запуск

Сначала запустите API по общей инструкции проекта. Из папки `Champ`:

```powershell
dotnet run --project .\desktop\Toir.Desktop.csproj -c Release
```

Либо после сборки откройте `desktop\bin\Release\net9.0-windows\Toir.Desktop.exe`.

При проверке обновления старое приложение оставалось открытым и блокировало этот EXE. Поэтому новая версия также собрана в **`desktop\bin\Updated\Toir.Desktop.exe`**. Старый процесс принудительно не завершался. Чтобы обновить обычный путь, закройте старое окно и выполните `dotnet build .\desktop\Toir.Desktop.csproj -c Release`. Параллельная сборка без закрытия: `dotnet build .\desktop\Toir.Desktop.csproj -c Release -p:OutputPath=bin/Updated/`.

В форме входа укажите `http://127.0.0.1:8000` **без `/api`**. Для демонстрационной БД:

| Пользователь | Пароль | Права |
|---|---|---|
| `admin@toir.local` | `ChampDemo2027!` | Полный доступ |
| `master@toir.local` | `ChampDemo2027!` | Объекты своего цеха |
| `engineer@toir.local` | `ChampDemo2027!` | Инженерные операции |
| `member@toir.local` | `ChampDemo2027!` | Своя бригада, переходы и материалы |
| `manager@toir.local` | `ChampDemo2027!` | Просмотр и отчёты |

Пароли относятся только к локальному учебному наполнению. Клиент запоминает адрес и email. Опция «Запомнить меня» сохраняет только refresh token, защищённый Windows DPAPI **CurrentUser**, а не открытый токен или пароль; повторный запуск проверяет сеанс через сервер и ротирует токен. Выход и отключение опции удаляют сохранённый секрет. DPAPI не защищает от вредоносного кода, уже работающего от имени того же пользователя Windows. Без опции токены остаются только в памяти.

Проект целится в `net9.0-windows`: он реально собран установленным на этом компьютере SDK **9.0.102**. Для подготовки к соревнованиям 2027 нужно согласовать ПО площадки и перенести target framework на поддерживаемую версию, например .NET 10 LTS. .NET 9 заканчивает поддержку 10 ноября 2026 года. Сейчас менять target без установленного и проверенного SDK не следует.

## Возможности

### Доработка под короткие сессии — 14.10.2026

Одинаковые карточки оборудования/заявки/бригады используют один механизм; вход после запуска и смены пользователя — один `StartSession`. Общие пространства имён вынесены в `GlobalUsings.cs`. Это убирает повторяющийся код без удаления календаря, отчётов, ролей или очереди. Добавлены сброс поиска/фильтров, открытие карточки по Enter/двойному щелчку для читателя, автоматическая недоступность действий без выбранной строки, видимый фокус кнопок и рамка выбранного дня. Отметка уведомления сразу обновляет текст и счётчик. Запоздалый ответ старой сессии не должен менять экран нового пользователя.

Полный клиент остаётся **1 481 физической строкой** C# + XAML (раньше 1 528), а не 250 строками. Это 19 файлов, включая 11 строк общих импортов; без тестов, сборок, библиотек и конфигурации. В старом коде некоторые строки содержат несколько операторов — объём нельзя оценивать только числом строк. Точный повторный подсчёт: `../scripts/count_code.ps1`.

Для тренировки с таймером **1,5 часа**: 10 минут на запуск и проверку связи, 50 минут на вход + один реестр + общую форму, 20 минут на ошибки/права/проверку сохранения, 10 минут на сохранение результата. Для **3 часов**: 15 минут на каркас, 90 минут на основной сценарий с заявкой, 35 минут на карточку/один отчёт, 30 минут на тесты и ошибки, 10 минут на сдачу. Это учебные ориентиры, не утверждение официального распределения модулей и не гарантия воспроизведения всего клиента за одну сессию.

Цель первой репетиции — замерить свой фактический темп на чистом проекте. В полном клиенте `ApiClient` + общая форма `Dialogs` + реестры `Resources` уже занимают около 500 строк: заучивать весь клиент одним листингом не следует. Если на площадке нельзя использовать заранее подготовленные файлы, таймер начинается с создания каркаса; разрешённость шаблонов нужно выяснить у организаторов.

- Вход, обновление access token, выход и разграничение разделов по серверным метаданным.
- Dashboard: шесть актуальных показателей, диаграммы состояний, активные заявки, ближайшие ТО на 7 дней и дефицит склада. Тренд показан только при наличии сопоставимой серверной истории, иначе это явно обозначено. Обновление раз в 60 секунд при открытом незаблокированном экране.
- Таблицы: серверные поиск, сортировка и страницы 25/50/100; фильтры цеха, статуса, приоритета/типа/дат заявок, модели оборудования и места хранения материала. Цвета отражают статусы, высокий приоритет и приближение/просрочку ТО.
- График ТО: настоящий месяц-календарь, переход между месяцами, выбор дня и таблица записей; создание заявки из выбранного ТО с переносом оборудования/норматива через сервер. Для просроченного ТО можно указать новое начало, мастер выбирается из списка действующих мастеров.
- Формы строятся из `/api/meta`, значения связей загружаются из `/api/lookups`. Поля можно менять на сервере без ручного переписывания каждой формы.
- Карточка оборудования: основная информация, заявки, ТО, история и создание заявки. Карточка заявки: сведения, таймлайн статусов и материалы. Действия: назначение бригады, переход статуса, фактические даты, отчёт, расход материалов. «Завершить работы» отправляет отчёт, фактическое окончание и дополнительные материалы в `/complete` одной серверной транзакцией; ранее списанные материалы повторно не добавляются. Обычная форма не меняет статус в обход специальной серверной операции.
- Карточка бригады: состав, контакты, активные заявки и плановая загрузка.
- Семь типов отчётов: простои, выполнение ТО, эффективность бригад, расход материалов и три реестра. Параметры периода/цеха, настоящий серверный предпросмотр с таблицей и диаграммой, PDF/XLSX/CSV, пользовательские шаблоны. Временная ссылка скачивается сразу, файл открывается системной программой.
- Панель уведомлений и непрочитанный счётчик; статусы прочтения локальны для пользователя и сервера. Хлебные крошки, индикаторы загрузки, toast на 2,5 секунды, подтверждение удаления и повтор при ошибке записи.
- F5 — обновить, Ctrl+F — поиск, Ctrl+N — добавить в текущем разделе, Ctrl+L — заблокировать. Тема, шрифт, ширина/порядок колонок сохраняются отдельно для пользователя.
- Блокировка через 15 секунд бездействия распространяется и на открытые формы. Разблокировка сохраняет введённые изменения. Если API недоступен, уже открытый сеанс можно разблокировать прежним паролем: проверяется солёный PBKDF2-хеш только в оперативной памяти. Новый вход без сервера невозможен.
- Последние успешно прочитанные данные доступны из локального кеша с явной пометкой времени. Ошибка доступа 403 не подменяется кешем.
- При сетевой ошибке изменения можно добавить в очередь с исходным `Idempotency-Key`; сервер защищает от повторного создания. По умолчанию повтор ручной. В очереди можно явно включить **автоотправку после восстановления связи**: проверка раз в 10 секунд, только в том же сеансе/сервере и вне модальных окон. При конфликте или отказе сервера запрос остаётся, автоотправка отключается для ручного решения. Запросы с паролем в очередь не записываются.
- Ошибки и сетевые сбои журналируются без тел запросов и токенов.

## Файлы клиента

По умолчанию `%LOCALAPPDATA%\Toir.Desktop` содержит настройки, кеш, очередь, журналы и папку `Exports`. Кеш — локальная копия производственных данных; он не является самостоятельной БД и не заменяет сервер. Для изолированных проверок путь можно задать переменной `TOIR_DESKTOP_DATA`.

`ApiClient.cs` — HTTP/кеш/очередь; `SecureSession.cs` — DPAPI; `Dialogs.cs` — вход и формы; `MainWindow.xaml.cs` — оболочка; `MainWindow.Resources.cs`/`Tables.cs` — реестры; `MainWindow.Details.cs` — карточки; `MainWindow.Schedule.cs` — календарь; `MainWindow.OrderActions.cs` — действия; `MainWindow.SessionUi.cs` — настройки/уведомления/очередь; `MainWindow.Dashboard.cs` — обзор; `ReportWorkspace.cs` — отчёты; `CompletionDialog.cs` — атомарное завершение; `App.xaml` — стили. Бывший `EnhancedViews.cs` распределён между тематическими partial-файлами. Рукописные исходники разделены на фрагменты до 250 физических строк; функции сохранены. Основной макет 1366×768, используется WPF-масштабирование и прокрутка. Окна ограничены рабочей областью экрана. Полный ручной проход на всех DPI ещё нужен.

## Границы реализации

Клиент предназначен для текущего контракта `../API_CONTRACT.md` и текущего тренировочного задания. Он не доказывает покрытие всех 199 конкурсных аспектов и не гарантирует балл. Внешние сервисы, требования окончательной версии задания и отдельное мобильное приложение этим проектом не подменяются. Изменения ролей/данных окончательно проверяются на сервере, даже если кнопка доступна в интерфейсе.

Вне сети доступны только ранее открытые данные. Нет первичного автономного входа и автоматического разрешения конфликтов. После автологина через сохранённый refresh token первая разблокировка требует доступного сервера, поскольку пароль не сохранялся. После успешного ввода пароля текущий сеанс можно разблокировать офлайн. При конфликте форма/очередь остаются для ручного решения. Мастера импорта в WPF нет (импорт есть в веб/API); уведомления локального интерфейса не заменяют плановый сервис доставки; календарь не поддерживает drag-and-drop. Исторические тренды не выдумываются.

В критериях есть напряжение между запретом клиентской бизнес-логики и требованием тестировать три расчётные функции Desktop. `PreviewRules.cs` — изолированные чистые вспомогательные функции для учебной проверки/предпросмотра; они **не определяют сохраняемые значения и не подменяют сервер**. Все реальные проверки дат, назначений, остатков и переходов выполняет API/SQL. Такое разделение следует отдельно показать эксперту; полное начисление баллов не гарантируется. Список пакетов и этот проект не доказывают соответствие правилу «60 дней» или инфраструктуре площадки.
