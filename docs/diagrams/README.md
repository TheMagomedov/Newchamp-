# Схемы ТОиР-Проф

- `schema_core.png` / `.svg` — 7 основных таблиц и 9 связей для запоминания.
- `schema_full.png` / `.svg` — все 18 таблиц и все 28 внешних ключей БД `ChampTraining_20261013` на момент генерации.
- `.mmd` — редактируемые исходники ER-диаграмм Mermaid; `.dot` — исходники Graphviz.
- `schema_metadata.json` — прочитанные из SQL Server таблицы, поля и внешние ключи.
- `use-cases.puml`, `activity.puml`, `classes.puml` — редактируемые UML-исходники PlantUML; рядом находятся готовые `.svg` и `.png`.

На ER-схемах показаны ключи и основные поля, а не полный перечень атрибутов. `PK` — первичный ключ, `FK` — внешний ключ, `?` — поле допускает NULL. Числа у концов связей показывают допустимое количество связанных строк. У `WorkOrders.ScheduleId` есть уникальный индекс, поэтому одной записи графика соответствует не более одной заявки. Правила `DELETE CASCADE` и `DELETE SET NULL` подписаны; остальные внешние ключи используют `NO ACTION`.

Полная ER-схема крупная: для чтения отдельных полей лучше открыть SVG и увеличить масштаб. В основной схеме внешние ключи к таблицам вне выбранных семи таблиц сохранены в списке полей, но соединительные линии за её пределы не рисуются.

Перегенерация из корня проекта:

```powershell
node scripts/render_schema.cjs ChampTraining_20261013
```

Генератор выполняет только `SELECT` системных метаданных. Он использует Windows-аутентификацию к локальному SQL Server и разрешает только имя БД с префиксом `ChampTraining_`. Нужны `sqlcmd`, Node.js, `@viz-js/viz` и `sharp`. Путь к Node-пакетам можно передать через `CODEX_NODE_MODULES`; по умолчанию указан runtime текущего компьютера.

## UML: просмотр и повторный экспорт

1. `use-cases.svg` — пять ролей, общие действия, include/extend и граница системы.
2. `activity.svg` — цикл заявки, назначение, проверка остатка, завершение и закрытие; ветви отказа.
3. `classes.svg` — логическая модель домена: 15 сущностей, атрибуты, ассоциации с кратностями и композиция строк расхода.

```powershell
./scripts/render_uml.ps1
```

Нужны Java и `tools/plantuml-1.2026.8.jar`. Использован официальный [релиз PlantUML](https://github.com/plantuml/plantuml/releases/tag/v1.2026.8), SHA-256: `5E1ECFA8ECD32C90B03BBF3B1EB6F020943F98AB0FCF4032BE31A0002EE2C462` (контроль повторяемости локального файла, не цифровая подпись). JAR — инструмент сборки, не часть приложения. Экспорт выполняется локально через встроенный [Smetana](https://plantuml.com/smetana02); отдельный Graphviz и отправка исходников на сервер не нужны. Допустимость инструмента на соревновании уточняется отдельно.

UML отражает учебную реализацию. Классы — логические доменные сущности: отдельных ORM-классов в сервере нет, используется SQLAlchemy Core. Сессии, аудит, ключи идемпотентности и служебные связи показаны на полной ER-схеме, а не смешаны с доменными классами. Интеграция 1С — демонстрационная заглушка, поэтому полноценный обмен с 1С в диаграммы не включён. Изображения построены и просмотрены; это не означает официального принятия диаграмм экспертами. Типы диаграмм и точный процесс сверяются с финальным заданием.
