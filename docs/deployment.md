# Развёртывание ТОиР-Проф: локальная учебная среда

Инструкция относится к проекту `C:\Users\magom\Desktop\Champ` и отдельной БД `ChampTraining_20261013`. Основной стек: FastAPI, Streamlit и нативный WPF-клиент. Vue сохранён как резерв. Это локальная тренировочная конфигурация, не инструкция промышленного размещения.

## Актуальный запуск Streamlit

На подготовленном компьютере достаточно открыть PowerShell в `Champ` и выполнить **`./run.ps1`**. Сайт: `http://127.0.0.1:8501`, API и Swagger: `8000` / `8000/docs`. Терминал должен оставаться открытым. Скрипт не закрывает чужие процессы: использует исправный существующий API либо запускает свой, который останавливает при выходе.

На новом компьютере `./setup.ps1` устанавливает API и Streamlit в отдельные `.venv` / `.venv-streamlit`, подготавливает учебную БД без сброса существующих таблиц и собирает WPF. `./setup_streamlit.ps1` устанавливает только новый веб из `web_streamlit/requirements.lock.txt`. Проверена Streamlit 1.64.0, Python 3.13.2. `pip check` завершён без конфликтов. Node.js для нового веба не нужен; Vue устанавливается только с `./setup.ps1 -LegacyWeb`.

Раздельный запуск: `./start.ps1`, затем в другом терминале `./start_streamlit.ps1`. Вход: учебный аккаунт `admin@toir.local`, пароль `ChampDemo2027!`. HTTP-клиент Streamlit обращается к локальному API без унаследованных прокси окружения. Токены хранятся в памяти отдельного Streamlit-сеанса, не в файле и не в URL. После обновления страницы браузера может понадобиться новый вход.

Для независимого проверочного стенда: `./run.ps1 -ApiPort 8010 -WebPort 8502`. Основные адреса не меняются. Тема и локальная привязка задаются в `.streamlit/config.toml`; приложение не опубликовано в интернете.

Ниже сохранены подробности API/WPF и резервного Vue. Указанный далее адрес `8000` открывает Vue, **не новый Streamlit**.

## Что должно быть установлено

- Windows и работающий SQL Server 2022 или совместимый более новый сервер. SSMS 20 — средство управления, а не версия сервера.
- Microsoft ODBC Driver 17 for SQL Server. Python-драйвер `pyodbc` использует установленный системный ODBC-драйвер.
- Python: фактически проверена версия 3.13.2. Окружение `.venv` уже создано на текущем компьютере.
- Node.js и pnpm: фактически использован Node 24.19.0. Зависимости web закреплены в `package.json` и `pnpm-lock.yaml`. На другом компьютере допустим npm, но для воспроизведения текущего lock-файла предпочтителен pnpm.
- .NET SDK 9.0.102 для сборки текущего `net9.0-windows`; для готового EXE — Windows Desktop Runtime 9. Проект следует перевести на поддерживаемый и разрешённый площадкой SDK перед конкурсом 2027; .NET 9 заканчивает поддержку 10 ноября 2026 года.

Пользователь Windows, запускающий подготовку, должен иметь право создать отдельную учебную БД и работать с её объектами. Имя SQL-инстанса уточняется в окне подключения SSMS; установленная программа SSMS сама сервер не создаёт.

## Первичная подготовка или повторная сборка

Откройте PowerShell в `Champ`:

```powershell
Set-Location -LiteralPath 'C:\Users\magom\Desktop\Champ'
.\setup.ps1
```

`setup.ps1` создаёт `.venv`, если её нет, устанавливает Python-зависимости из `backend/requirements.lock.txt`, запускает `scripts/setup.py` и `setup_streamlit.ps1`, затем собирает WPF. Только с ключом `-LegacyWeb` использует pnpm/npm и собирает Vue. Доступ в интернет нужен при отсутствии локального кеша зависимостей. На конкурсной площадке версии и возможность установки согласуются заранее.

Перед повторной сборкой закройте старое окно WPF: работающий EXE блокирует замену файла. При обновлении 13.10.2026 старое окно оставлено нетронутым, поэтому новая версия отдельно собрана в `desktop/bin/Updated/Toir.Desktop.exe`. База не пересоздавалась.

`backend/requirements.txt` — короткий список прямых зависимостей для разработчика. Установщик использует `requirements.lock.txt`: снимок фактически проверенного окружения Windows/Python 3.13.2 со всеми прямыми и транзитивными пакетами приложения и тестов. После изменения зависимостей сначала повторите проверки, затем осознанно обновите lock-файл. Это фиксация версий, а не подтверждение соответствия конкурсному правилу 60 дней или гарантия идентичных бинарных файлов на иной платформе.

При первом запуске `scripts/setup.py` создаёт `.env` со случайным секретом и отдельную БД. В пустой БД последовательно применяются `database/01_schema.sql`, `02_rules.sql`, `03_seed.sql`, затем добавляются демонстрационные аккаунты и заявки. При повторном запуске существующие таблицы и бизнес-данные не сбрасываются. Скрипт не является механизмом миграций: изменения SQL после создания схемы нужно применять осознанно к учебной БД. Сам `01_schema.sql` намеренно отказывается выполняться в непустой БД.

Параметры `.env`: `CHAMP_DATABASE`, `CHAMP_SERVER`, `CHAMP_DRIVER`, `CHAMP_SECRET`. Для текущей установки база — `ChampTraining_20261013`, сервер по умолчанию — `localhost`. Если используется именованный инстанс, замените только `CHAMP_SERVER` на фактическое имя. Не публикуйте `.env`; он исключён из Git. При переносе на другой компьютер создайте виртуальное окружение заново: копирование `.venv` не обеспечивает переносимость.

## Запуск и проверка

```powershell
.\start.ps1
```

Сервер остаётся в текущем терминале. Откройте:

- `http://127.0.0.1:8000` — собранный веб-клиент;
- `http://127.0.0.1:8000/docs` — интерактивную документацию API;
- `http://127.0.0.1:8000/openapi.json` — описание API;
- `http://127.0.0.1:8000/api/health` — проверку подключения к БД.

После изменения Python-кода остановите ранее запущенный сервер через `Ctrl+C` в его терминале и повторите запуск. `start.ps1` проверяет занятый порт и не завершает чужие процессы: сообщение о работающем API не означает, что старый процесс уже загрузил новый код. Для осознанного запуска отдельного стенда можно указать `./start.ps1 -Port 8010` и тот же порт в клиенте; основной учебный адрес остаётся `8000`.

Если PowerShell запрещает запуск `.ps1`, выполните ту же команду напрямую, не меняя системную политику:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Для текущего обновления запустите `desktop\bin\Updated\Toir.Desktop.exe`. После закрытия старого клиента можно собрать стандартный Release и запустить `desktop\bin\Release\net9.0-windows\Toir.Desktop.exe` либо во втором терминале:

```powershell
dotnet run --project .\desktop\Toir.Desktop.csproj -c Release
```

В WPF укажите адрес `http://127.0.0.1:8000`, без `/api`. Для входа администратора используйте `admin@toir.local` / `ChampDemo2027!`. Остальные учебные аккаунты перечислены в [руководстве пользователя](user-guide.md). Остановка API — `Ctrl+C`; SQL Server и данные не удаляются. После изменения web выполните повторную сборку и перезапустите API, чтобы он подключил актуальную папку `web/dist`.

## Проверки после развёртывания

```powershell
.\test.ps1
.\test.ps1 -Integration
dotnet run --project .\desktop\checks\DesktopChecks.csproj -c Release
dotnet run --project .\desktop\checks\DesktopChecks.csproj -c Release -- --live
```

`test.ps1` проверяет лимит 250 строк, запускает пять конкурсных MSTest-методов, доменные Python-тесты и Streamlit-тесты; ключ `-Integration` добавляет полный pytest-набор с учебной БД. JS-тесты резервного Vue запускаются только с `-LegacyWeb`. Конкурсные Desktop-тесты используют зафиксированные NuGet-зависимости; первая установка требует их наличия в кеше или доступа к источнику пакетов.

Для SQL откройте новое окно запроса SSMS, явно выберите `ChampTraining_20261013` и выполните целиком `database/04_selftest.sql`. Подтверждены 39 SQL-проверок, 66 pytest-проверок, 5 MSTest-методов, 18 автономных и 39 live-проверок WPF, 40 JS-тестов. Подробности и ограничения — в [покрытии](coverage.md). SQL-тесты откатывают фикстуры; пропуски IDENTITY/SEQUENCE после тестов допустимы. Live-проверки создают уникальные временные записи и удаляют их; журналы и аудит тестовых действий могут сохраниться.

## Безопасность, журналы и восстановление

API привязан только к `127.0.0.1`. SQL-подключение использует `Trusted_Connection=yes;Encrypt=yes;TrustServerCertificate=yes`: аутентификацию Windows и доверие локальному сертификату. Демо-пароли, HTTP на loopback, токены web в `sessionStorage`, лимиты в памяти одного процесса и такое доверие сертификату допустимы здесь только как учебные решения. Не открывайте сервер наружу простым изменением host. HTTPS, управление секретами, резервирование, общие лимиты нескольких процессов и эксплуатационная защита отдельно не внедрялись.

Журнал API — `runtime/api.log`. WPF хранит журнал, кеш, очередь и выгрузки в `%LOCALAPPDATA%\Toir.Desktop`. Перед существенными изменениями сделайте резервную копию именно учебной БД через SSMS; резервное копирование по расписанию не настроено. Не удаляйте локальную очередь до проверки её операций на сервере.

Если вход не работает, проверьте `/api/health`, запущенный SQL-инстанс и `.env`. Ошибка ODBC означает отсутствие/несовпадение драйвера. Ошибка занятого порта требует проверить существующий процесс API. Ответ 429 означает превышение лимита: дождитесь указанного времени, не запускайте несколько наборов проверок одновременно.
