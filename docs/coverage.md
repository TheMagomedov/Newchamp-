# Покрытие тренировочного задания и оставшаяся работа

Это сопоставление реализации с основными блоками предоставленного задания. Оно не заменяет финальную ведомость оценивания, не утверждает выполнение всех 199 аспектов и не обещает 100 баллов. Исходные документы содержат противоречия; окончательное задание изменяется минимум на 30%. После выдачи финальной версии нужно заново связать каждую строку критериев с кодом и демонстрацией.

## Обновление 14.10.2026: основной веб — Streamlit

По запросу пользователя создан `web_streamlit/`, новый адрес — `http://127.0.0.1:8501`. Вход/роли, шесть KPI, пять блоков аналитики, карточки, CRUD, календарь, заявки/материалы, импорт, поиск, уведомления и PDF/XLSX/CSV работают через существующий API. `web/` с Vue оставлен как резерв. API и WPF разделены на тематические файлы, без удаления функций; все активные исходники и тесты не длиннее 250 физических строк. SQL и резервный Vue не входят в этот лимит.

Новый веб прошёл **117 автоматических проверок**: 40 HTTP-клиента, 46 Streamlit AppTest и 31 разбора выбора на диаграмме. Проверены роли, страницы/карточки, формы, валидация, сохранение версии, подтверждения, атомарное завершение, шаблоны и выгрузка. AppTest использует подставной API и не доказывает реальную работу каждого браузера или SQL. Общий прогон сохранил 66 backend-тестов и пять конкурсных MSTest. Количество тестов — не баллы.

Для Streamlit есть отличия от Vue: обновление раз в минуту через fragment/polling, не клиентский SSE; шаблоны и прочтения живут только в сеансе; интерфейс и адаптивность основаны на стандартных Streamlit-виджетах, а не на прежнем точном макете. Не обещаны тот же responsive-дизайн, удержание фокуса модальных окон, печать точной страницы или нормативы 10 Мбит/с/100 пользователей. Исторические данные не подменяются вымышленными значениями. Прежнюю предварительную оценку Vue нельзя автоматически присвоить Streamlit.

Ниже — веса критериев и ранее проверенные свойства полного комплекта, включая резервный Vue. Там, где прямо написано Vue/JS/SSE, это не доказательство соответствующего свойства Streamlit.

### Как понимать цель «60+»

По предоставленной книге критериев WPF и web вместе имеют потолок **37,8 балла**. Для цели 60+ нужен весь технический комплект: проектирование, БД, API, оба клиента и тестирование.

Добавленные функции закрывают ранее отсутствовавшие части этих блоков, но подтверждённого результата «60» пока нет: нужен построчный экспертный прогон всех аспектов. Только API + БД + два клиента + тесты без UML имеют потолок 68,75, поэтому потеря нескольких групп требований быстро опускает результат ниже 60. Число не выводится из суммы прошедших автотестов.

Базу обслуживает только backend. Оба интерфейса используют API; WPF не содержит WebView и прямой строки SQL-подключения. Сервер реализован как одно приложение с модулями, а не набор независимо развёрнутых микросервисов. Динамические формы экономят повторяющийся код, но не уменьшают фактическую сложность правил и проверки.

## Чего нет или что реализовано ограниченно

Отдельного мобильного клиента нет. Нет микросервисного шлюза, распределённых сервисов авторизации/уведомлений, фоновой рассылки или доказанного нагрузочным тестом обслуживания 100 одновременных пользователей и 10 000 единиц оборудования. endpoint интеграции 1С явно возвращает учебную заглушку; реального подключения к 1С нет. Web использует SSE, но сервер проверяет изменение доступных пользователю данных опросом БД раз в две секунды; это не доказательство масштабирования. WPF использует минутный опрос.

WPF сохраняет ранее загруженные ответы и очередь, но не предоставляет автономную БД или новый вход без сервера. По умолчанию повтор ручной; опциональная автоотправка использует прежний ключ и только тот же сервер/аккаунт, а при конфликте останавливается. Web не имеет заявленного режима автономной работы. Шаблоны и отметки прочитанных уведомлений хранятся локально. Токены web находятся в `sessionStorage`; это часть локальной учебной версии, не утверждение о готовой промышленной защите. Лимиты запросов и временные файлы экспорта находятся в памяти одного процесса. HTTPS-развёртывание, резервирование и распределённые ограничения отдельно не построены.

Не созданы оформленное руководство развёртывания DOCX/PDF на 8–10 страниц и презентация на 12–15 слайдов. Markdown-документы содержат полезную основу, но не подменяют требуемый формат. Все три UML экспортированы и просмотрены, однако формальная приёмка диаграмм остаётся за экспертами. Полный ручной проход WPF по всем ролям, DPI и сценарию потери связи остаётся отдельной приёмкой.

В текущей трактовке простой считается по фактически прошедшему времени, а не по производственному календарю смен. Открытый период ограничен текущим временем. Следующая календарная дата ТО рассчитывается только для периодичности в днях; моточасы/состояние требуют дополнительных исходных данных. Эти решения нужно сверить с официальными ответами экспертов.

## Как использовать проект в подготовке

Полный проект существенно больше **300 строк на сессию**. Это работающий тренировочный образец для понимания связей, типовых операций и последовательности разработки, а не обещание воспроизвести весь объём из 1500 заученных строк. Выделяйте из него короткие учебные блоки, воспроизводите их самостоятельно и измеряйте время без копирования готового проекта.

Перед конкурсом зафиксируйте разрешённый стек и версии, отдельно уточните мобильный клиент, микросервисы, число сессий, тесты и спорные правила БД. Затем составьте таблицу «аспект → реализация → демонстрация», выполните 15-часовую репетицию и сохраните результаты проверки. Правила использования ИИ и готовых материалов на самой площадке определяются конкурсом; эта подготовительная работа не отменяет их.
