# ТОиР-Проф — конкурсный учебный проект

Рабочее локальное приложение по предоставленному сценарию: **WPF + Python/FastAPI + SQL Server + Streamlit**.
SQL Server хранит данные; SSMS — программа для управления им. Оба клиента работают только через REST API.

По запросу пользователя основной веб переведён на Python/Streamlit. Прежний Vue в `web/` сохранён как резерв, а не удалён. Его изучать для Python-маршрута не нужно. Перенос не означает автоматического сохранения всех баллов за точную вёрстку и браузерные взаимодействия.

## Первый запуск после клонирования

Нужны Windows, Git, Python 3.13 (проверено на 3.13.2), .NET SDK 9, SQL Server 2022 и Microsoft ODBC Driver 17 for SQL Server. SSMS сам по себе не заменяет установленный SQL Server. Для основного веба Node.js не нужен.

```powershell
git clone https://github.com/TheMagomedov/Newchamp-.git
cd Newchamp-
./setup.ps1
./run.ps1
```

Установщик создаёт два Python-окружения, отдельную учебную БД `ChampTraining_20261013`, демонстрационные записи и собирает WPF. Нужен доступ к загрузке зависимостей и право текущего пользователя Windows создавать БД на локальном SQL Server. `.env` со случайным секретом создаётся локально и в репозиторий не входит. Если ваш SQL Server — именованный инстанс, после первой попытки установки исправьте `CHAMP_SERVER` в созданном `.env` и повторите `./setup.ps1`; остальные параметры, включая секрет, сохраните.

После запуска веб доступен на <http://127.0.0.1:8501>, API — на <http://127.0.0.1:8000/docs>. WPF запускается отдельно: `desktop/bin/Release/net9.0-windows/Toir.Desktop.exe`. База с данными текущего компьютера, окружения и готовые сборки не публикуются: они создаются при установке. SQL-скрипты, тесты, диаграммы и резервный Vue включены; Vue собирается по желанию командой `./setup.ps1 -LegacyWeb`.

Это локальный учебный стенд с публичными демонстрационными учётными данными, не готовая конфигурация для размещения в интернете. Подробнее: [развёртывание](docs/deployment.md).

## Быстрый запуск на уже настроенном компьютере

База `ChampTraining_20261013` уже создана отдельно от остальных баз. Окружения API (`.venv`) и нового веба (`.venv-streamlit`) изолированы друг от друга.

1. В PowerShell перейдите в `C:\Users\magom\Desktop\Champ`.
2. Выполните **`./run.ps1`** — одна команда для API и Streamlit. Она использует уже работающий API или запускает свой; при выходе останавливает только свой процесс. Терминал оставьте открытым.
3. Основной веб: <http://127.0.0.1:8501>. Swagger: <http://127.0.0.1:8000/docs>. Адрес `8000` всё ещё открывает резервный Vue, а не Streamlit. Для раздельного запуска: `./start.ps1` и во втором терминале `./start_streamlit.ps1`.
4. Обновлённый Desktop: `desktop/bin/Updated/Toir.Desktop.exe`. Закройте старое окно WPF перед запуском новой версии. Стандартная папка после обычной сборки — `desktop/bin/Release/net9.0-windows`.

Если API уже был запущен до обновления, остановите **его в своём терминале** через `Ctrl+C` и снова выполните `./start.ps1`. Старый процесс не перечитает изменённый Python-код сам. Данные БД при этом сохраняются. Порты `8010`/`8502` используются только для временной проверки; рабочие адреса — API `8000` и Streamlit `8501`. При первом переносе на другой компьютер для веба выполните `./setup_streamlit.ps1`.

При ограничении запуска PowerShell-скриптов можно выполнить напрямую:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Учебные аккаунты: `admin@toir.local`, `engineer@toir.local`, `master@toir.local`, `member@toir.local`, `manager@toir.local`.
Общий **демонстрационный** пароль: `ChampDemo2027!`. Это вымышленные учётные записи локального стенда.

## Реализовано

Детальный список ниже описывает полный комплект и возможности сохранённого Vue. Основной Streamlit использует тот же API; его интерфейс, автоматическое обновление и набор браузерных взаимодействий проверяются отдельно. Не переносите прежнюю оценку Vue на Streamlit без контрольного прогона критериев.

- Оборудование, цеха, типы ТО, график, заявки, бригады, склад, поставщики и пользователи.
- Пять ролей; мастер ограничен своим цехом, участник бригады — своими заявками. Руководитель читает, инженер не списывает материалы.
- История статусов, журнал операций, ограничения дат, запрет возвращения списанного оборудования и пересекающихся работ одной бригады.
- Транзакционное списание/возврат материалов с сохранением цены на момент расхода.
- JWT на 1 час, refresh на 7 дней с ротацией, хеширование PBKDF2, отзыв сессий, лимит 100 запросов в минуту на пользователя.
- Идемпотентные записи: повтор с тем же ключом не создаёт дубликат даже после перезапуска API.
- Фильтрация, пагинация, сортировка, аналитика, PDF/XLSX/CSV, временные ссылки на 15 секунд, атомарный импорт оборудования.
- В WPF: календарь ТО, подробные карточки и история, бригады, фильтры, уведомления, горячие клавиши и настройки интерфейса; семь видов отчётов с предпросмотром и диаграммами.
- В WPF: блокировка через 15 секунд, локальный журнал, кеш, ручная очередь и отдельно включаемая автоотправка. Опция «Запомнить меня» шифрует refresh-токен средствами Windows DPAPI, а не сохраняет пароль.
- В Vue: шесть KPI, все пять разделов аналитики, интерактивные диаграммы, календарь, поиск, уведомления, фильтры и шаблоны; PNG/CSV, PDF блоков и всей аналитики, печать страницы.
- Vue получает авторизованные SSE-события с резервным опросом; Streamlit использует минутное обновление фрагмента, WPF — минутный опрос. Недоступные исторические тренды обозначены явно, а не подменены нулевыми данными.
- Создание заявки из графика защищено от дублей. WPF завершает заявку с дополнительными материалами одной серверной транзакцией.
- ER-схемы и три UML-диаграммы сохранены в PNG/SVG вместе с редактируемыми исходниками.

## Проверки

### Объём рабочего кода после доработки WPF (14.10.2026)

| Часть | Рабочие файлы | Физические строки | Непустые строки |
|---|---:|---:|---:|
| Backend — Python/FastAPI | 17 | 1 654 | 1 515 |
| Frontend — Python/Streamlit | 13 | 1 488 | 1 341 |
| Desktop — C# + XAML/WPF | 19 | 1 481 | 1 448 |
| **Всего** | **49** | **4 623** | **4 304** |

Подсчёт воспроизводится командой `./scripts/count_code.ps1`. В физические строки включены импорты, комментарии и пустые строки. Исключены БД, тесты/проверки, конфигурация, команды запуска, документация, зависимости, сборки и резервный Vue. Это именно код приложений, не весь объём подготовки. Непустая строка также не равна одному оператору: старый код содержит длинные составные строки. WPF уменьшен с 1 528 до 1 481 строки, одновременно улучшены выбор записи, карточки и безопасность смены сеанса.

Сессия 1,5–3 часа не означает, что весь этот комплект реально написать с нуля за одну сессию. Учебный порядок и план контрольного прогона с резервом на проверку описаны в `desktop/README.md`. Лимит 250 — размер отдельного исходного файла, не доказательство времени выполнения или баллов.

```powershell
.\test.ps1
# Дополнительно — API/SQL-интеграция с настроенной учебной БД:
.\test.ps1 -Integration
# По желанию — сохранённый Vue (потребуется pnpm):
.\test.ps1 -LegacyWeb
sqlcmd -S localhost -E -C -b -d ChampTraining_20261013 -i database\04_selftest.sql -f 65001
dotnet build desktop\Toir.Desktop.csproj -c Release -p:OutputPath=bin/Updated/
```

Интеграционные проверки работают с отдельной учебной БД. Они создают собственные временные записи; SQL-проверки откатывают фикстуры. Identity/sequence могут иметь пропуски после отката — это нормально.

Актуальные результаты и непроверенные аспекты — в `docs/coverage.md`. Количество тестов не является количеством конкурсных баллов.

## Границы этой версии

Это развёрнутый учебный проект, а не подтверждение 100 баллов. Финальный вариант задания меняется минимум на 30%; спорные формулы и правила необходимо согласовать с экспертами. Полный исходный код не укладывается в 300 строк за сессию — учить следует по блокам и по контрольным сценариям.

WPF собирается под установленный `.NET 9`. Для соревнования 2027 следует перейти на разрешённую поддерживаемую версию SDK и повторить сборку. На площадке надо проверить версии всех прямых и транзитивных библиотек по правилу 60 дней, доступный ODBC и разрешённые инструменты генерации.

Мобильный клиент, отдельные микросервисы/шлюз, реальная 1С, рассылки, конкурсная PPTX-презентация и финальная вёрстка документов не входят в текущую реализацию. Заглушка 1С явно обозначена. Перечень проверенных и непроверенных пунктов приведён в `docs/coverage.md`.

API слушает только 127.0.0.1. SQL использует Windows-аутентификацию и доверие локальному сертификату. `.env` содержит случайный секрет, исключён из Git. Это настройки локальной тренировки: для внешнего размещения нужны HTTPS, проверяемый сертификат SQL и отдельный пользователь БД с ограниченными правами.

## Порядок изучения

### Учебное правило: не больше 250 строк в файле

Основные исходники Python API, WPF и Streamlit разделены по смыслу, без удаления функций и без упаковки кода в `exec`/однострочные трюки. В лимит входят пустые строки и комментарии. SQL и резервный Vue исключены из этого учебного маршрута. Проверка:

```powershell
.\scripts\check_fragments.ps1
```

Один файл — один фрагмент, **не одна конкурсная сессия**. Разбиение не превращает весь проект в 250 строк: суммарный объём остаётся большим. Цель — изучать и воспроизводить небольшие понятные части, а не заучивать весь листинг. Для начала возьмите только вход → один список → одну форму → одну заявку; аналитика и дополнительные удобства идут после этого.

| Этап | Фрагменты для изучения | Что уметь сделать без подсказки |
|---|---|---|
| 1. Python HTTP | `web_streamlit/api_client.py`, `backend/app/auth.py` | Войти, получить список, объяснить 401 и 403 |
| 2. Веб на Python | `web_streamlit/app.py`, `common.py`, `forms.py`, `resources_view.py` | Открыть раздел, создать и изменить разрешённую запись |
| 3. Заявки и ТО | `web_streamlit/work_orders.py`, `schedule.py`, `backend/app/workflows.py` | Пройти жизненный цикл, не создать дубль, обработать нехватку материала |
| 4. WPF | `desktop/ApiClient.cs`, `Dialogs.cs`, `MainWindow.Resources.cs`, `MainWindow.Tables.cs` | Повторить тот же сценарий в Windows-клиенте |
| 5. Дополнения | Карточки, календарь, dashboard и отчёты — в отдельных тематических модулях | Показать данные и выгрузить результат |
| 6. Проверка | `desktop/tests/PreviewRulesTests.cs`, затем остальные тесты | Объяснить пять конкурсных тестов и исправить намеренно внесённую ошибку |

БД по просьбе пользователя изучается отдельно. Работа через SSMS не отменяет время на создание ключей, ограничений и нужных серверных правил.

### Полный технический маршрут

1. `01_schema.sql`: сначала цеха/пользователи/оборудование, затем заявки, график и материалы.
2. Изучить основные связи на `docs/diagrams/schema_core.png`, потом полную схему.
3. Запустить `04_selftest.sql` и объяснить, почему каждый запрещённый сценарий отклоняется.
4. `backend/app/domain.py` → `resources.py` → `auth.py` → `api.py` → `reports.py`.
5. Пройти полный сценарий: создать заявку → назначить → начать → списать материал → завершить → закрыть → выгрузить отчёт.
6. Повторить самостоятельно на чистой учебной БД и затем провести 15-часовой прогон.
